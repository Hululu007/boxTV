# boxTV 电脑端便携化改造方案（2026-11-09）

## 一、背景与目标

原电脑端（boxTV-host，Compose Desktop）通过 MSI 安装包交付，存在两个突出问题：

1. **开发调试低效**：每次代码变更后需重新打包 MSI → 重新安装 → 再验证，流程繁琐；
2. **升级不便**：版本迭代要走「安装覆盖 / 卸载重装」，涉及安装器、注册表、快捷方式等系统操作。

本次改造目标：

- 移除 MSI 方案，改为**免安装绿色便携版**：解压即可运行；
- 保留原 MSI 安装版的**全部功能特性**（配置读写、依赖加载、系统适配）；
- 后续升级仅需**替换解压目录内文件**，无任何安装/卸载/注册表操作；
- 开发调试直接 `gradlew run`，交付一键 `gradlew deliverPortable`。

## 二、方案选型

| 候选方案 | 说明 | 结论 |
|---|---|---|
| jpackage 应用镜像 + zip（**采用**） | Compose Desktop `createDistributable` 产出应用镜像（自带精简 JRE + 全部依赖 + exe 启动器），打成 zip | 解压即用、零配置；与原 MSI 内部的应用镜像完全同源，功能无差异 |
| ShadowFatJar（单一 fat jar） | 需用户机器自备 JRE 21 | 违背开箱即用；ffmpeg/资源路径也要另行适配 |
| 现有 MSI 精简 | 仍需安装流程 | 不满足改造目标 |

**核心原理**：原 MSI 本质就是「jpackage 应用镜像 + WiX 安装壳」。去掉 WiX 安装壳、保留应用镜像并打成 zip，即得到功能完全一致的便携版——这不是功能阉割，而是同一实体的不同封装。

## 三、改造内容

### 3.1 构建脚本（boxTV-host/build.gradle.kts）

- `targetFormats(TargetFormat.Msi)` → `TargetFormat.AppImage`；
- 删除 MSI 专属配置 `windows { menu/shortcut/dirChooser/perUserInstall/upgradeUuid }`（均为安装器行为，便携版不适用）；
- 删除 `packageMsiWithUninstaller`（jpackage+WiX 注入卸载快捷方式）与 `deliverMsi` 任务；
- 新增任务：
  - `packagePortable`：`createDistributable` 产出应用镜像 → 打成 `boxTVHost-<版本>-portable-win64.zip`（zip 根为 `boxTVHost/` 文件夹，解压不散落文件）；
  - `deliverPortable`：复制 zip 到根目录 `deliverables/` 统一交付；
- 版本参数重命名：`msiVersion` → `appVersion`（当前 1.2.3，与 `HostServer.VERSION` 对齐）。

### 3.2 删除的文件

- `boxTV-host/packaging/msi/main.wxs`（WiX 卸载快捷方式注入模板，仅 MSI 使用）；
- `deliverables/boxTVHost-1.0.0.msi`（旧 MSI 产物）。

### 3.3 源码改动

- [AutoStartManager.kt](../boxTV-host/src/main/kotlin/com/example/boxtv/host/core/AutoStartManager.kt)：仅更新注释（便携版下 Run 注册表键的清理语义），**逻辑零改动**；
- 其余源码（Main/ConfigStore/FirewallManager/TrayManager/UpdateStore/HostServer 等）**零改动**。

## 四、功能保留对照表

| 功能 | 原 MSI 版 | 便携版 | 说明 |
|---|---|---|---|
| 运行环境 | 自带 JRE（安装到 Program Files） | 自带 JRE（在解压目录 `runtime\`） | 用户机器无需安装 Java |
| HTTP 服务 8964 / UDP 发现 8965 | ✔ | ✔ | 端口绑定与安装方式无关 |
| 配置文件 config.json | `%APPDATA%\boxTV\` | `%APPDATA%\boxTV\`（不变） | 配置与程序目录解耦，换目录/换版本自动保留 |
| 配对数据 / 访问日志 / 缩略图缓存 / TV 更新发布 | `%APPDATA%\boxTV\` 下 | 同左（不变） | 同上 |
| ffmpeg 工具链 | `<安装目录>\app\resources\tools\` | `<解压目录>\app\resources\tools\` | 运行时经 `compose.application.resources.dir` 定位，随包分发 |
| 开机自启 | 写 `HKCU\...\Run`（指向 exe） | 同左，**功能完全可用** | exe 启动器路径稳定；目录移动后需重新开启自启以刷新路径 |
| Windows 防火墙引导 | netsh 按端口加规则（UAC 提权） | 同左 | 规则按端口（8964/TCP、8965/UDP）而非 exe 路径，与安装方式无关 |
| 系统托盘 / 关闭到托盘 | ✔ | ✔ | 纯 AWT 实现，无安装耦合 |
| TV 端局域网更新发布 | ✔ | ✔ | `%APPDATA%\boxTV\update\`，与安装方式无关 |

## 五、交付物与使用方式

- 交付物：`deliverables/boxTVHost-<版本>-portable-win64.zip`
- 使用：
  1. 解压 zip 到任意目录（如 `D:\boxTV\`，得到 `boxTVHost\` 文件夹）；
  2. 双击 `boxTVHost\boxTVHost.exe` 运行，无任何额外配置；
  3. 如需常驻：可手动为 `boxTVHost.exe` 创建桌面/开始菜单快捷方式（可选）。

## 六、版本升级流程（关键改进）

1. 修改代码后同步版本号：`HostServer.VERSION` 与 `build.gradle.kts` 的 `appVersion`；
2. 执行 `gradlew deliverPortable` 生成新 zip 并复制到 `deliverables/`；
3. 用户侧升级：**关闭运行中的 boxTVHost → 将新解压目录内的文件覆盖/替换旧目录 → 重新运行**。

- 配置、配对、缓存均在 `%APPDATA%\boxTV\`，替换程序文件不影响任何用户数据；
- 无安装、无卸载、无注册表残留；如开启了开机自启且**目录路径发生变化**，需在设置中关闭再重新开启自启（更新 Run 键中的 exe 路径）；路径不变则无需任何操作。

## 七、开发调试流程（关键改进）

| 场景 | 命令 | 说明 |
|---|---|---|
| 日常开发调试 | `gradlew run`（boxTV-host 目录） | 直接以源码运行，**无需打包、无需安装**，改完即跑 |
| 单元测试 | `gradlew test` | JUnit 5 |
| 出便携包 | `gradlew deliverPortable` | 一条命令产出 zip 到 `deliverables/` |

注：开发模式（`gradlew run`）下进程为 java.exe，开机自启功能自动置灰（防污注册表），属既有保护逻辑，与本次改造无关。

## 八、卸载方式

便携版无系统级安装，卸载即：

1. 关闭 boxTVHost（托盘也退出）；
2. 删除解压目录；
3. （可选清理）设置中关闭开机自启；如未关闭，注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 中的 `boxTV` 值指向已删除路径，Windows 启动时静默忽略，无副作用；
4. （可选清理）删除 `%APPDATA%\boxTV\`（配置/缓存/配对数据）与防火墙规则：
   ```bat
   netsh advfirewall firewall delete rule name="boxTV Host"
   ```

## 九、验证结论

- `deliverPortable` 产物 zip 包含：`boxTVHost.exe` 启动器、`app\`（应用 jar + ffmpeg 工具链）、`runtime\`（精简 JRE），与原 MSI 内部应用镜像结构一致；
- 解压后双击 exe 即可启动服务（HTTP 8964 + UDP 8965），配置落在 `%APPDATA%\boxTV\`，与历史 MSI 安装的数据互通。
