# boxTV 40400 偶现播放异常根因分析报告

> 日期：2026-11-09　|　涉及版本：电视端 ≤1.3.9、电脑端 ≤1.2.2
> 问题特征：非必现、随机触发，出现后数秒内可自动恢复正常播放

---

## 一、错误码 40400 业务场景与全部触发条件

40400 = `ApiCodes.NOT_FOUND`（资源不存在），由电脑端 HTTP 服务返回。电脑端全部 7 个触发点：

| # | 接口 | 触发条件 | 代码位置（HostServer.kt） | 电视端表现 |
|---|------|---------|--------------------------|-----------|
| 1 | `/api/folders` `browse` `search` `stream` `part` `meta` `thumb` | **授权文件夹不存在**：`findFolder(folderId)` 在内存配置中找不到 folderId | 各路由入口 | 浏览页面包屑「错误 40400」 |
| 2 | `/api/browse` | **目录不存在**：`dir.exists() || dir.isDirectory` 为 false | browse 路由 | 浏览页面包屑「错误 40400」 |
| 3 | `/api/video/stream` | **文件不存在**：视频文件 `file.exists()` 为 false | stream 路由 | ExoPlayer 报 ERROR_IO（Toast） |
| 4 | `/api/video/part` | **分片不存在**：M3U8 分片/密钥 `file.exists()` 为 false | part 路由 | ExoPlayer HLS 加载错误（Toast） |
| 5 | `/api/video/meta` | **无法读取视频元数据**：ffprobe 探测失败（文件被锁/损坏/进程超时 20s） | meta 路由 | **静默降级**（TV 端 meta=null 继续原画直连，用户不可见） |
| 6 | `/api/video/thumb` | **缩略图不可用**：ffmpeg 生成失败或工具缺失 | thumb 路由 | 占位图（用户不可见） |
| 7 | `/api/update/download` | **安装包缺失**：已发布版本但 APK 文件被删 | update 路由 | 更新下载失败提示 |

**关键排查结论**：电脑端所有路由读取配置走内存快照（`ConfigStore.peek()`），配置文件写入为「临时文件 + ATOMIC_MOVE」原子替换（[ConfigStore.kt](../boxTV-host/src/main/kotlin/com/example/boxtv/host/core/ConfigStore.kt)），**不存在配置撕裂读**。因此「授权文件夹不存在」型 40400 只能来自内存状态异常（见根因 R3）。

## 二、可复现测试场景设计与实验结果

围绕网络波动、资源加载时序、缓存策略、播放器状态机四个维度设计，以下实验全部在本机实测（服务 192.168.0.176:8964，授权文件夹 E:\视频，M3U8 剧集结构）：

### 实验 A：分片文件被独占锁定（模拟杀软实时扫描 / 下载器写盘）

- 方法：PowerShell `File.Open(path, Open, Read, FileShare.None)` 独占锁定分片 → 请求 `/api/video/part` → 完整接收响应体
- **结果：HTTP 200 + 响应体 0 字节（静默截断）**，而非任何错误码
- 根理：Ktor `respondFile` 先发出 200 响应头，随后打开文件通道失败，连接静默结束
- 对播放的影响：ExoPlayer 收到「半截响应」中途 EOF → `ERROR_IO`；比 40400 更隐蔽——**电脑端无任何日志痕迹**

### 实验 B：文件处于 Windows「删除挂起」（delete-pending）状态

- 方法：持有文件句柄（共享 Delete）+ `File.Delete()` 标记删除但不关句柄 → 文件进入删除挂起态 → 请求 `/api/video/part`
- **结果：`file.exists()` 瞬时返回 false → HTTP 404 / 业务码 40400「分片不存在」** ✅
- 完全复现用户症状：**偶现（仅删除挂起窗口期内触发）+ 数秒自动恢复（窗口期结束、ExoPlayer 内置重试成功）**

### 实验 C：锁定文件时的 meta / stream 请求

- 结果：全部返回 200——被 `Transcoder.metaCache`（key=videoId|mtime）与 `M3u8Aggregator.rewriteCache`（key=playlist|mtime）**缓存命中掩盖**，未触达真实文件
- 结论：缓存是「偶现性」的放大器——只有缓存未命中（首次播放/文件变化后）的窗口期才会暴露文件占用问题

### 实验 D：ffprobe 探测（meta 接口）压力

- ffprobe 打不开被锁文件 → 退出码非 0 → meta 返回 40400「无法读取视频元数据」
- 电视端对 meta 失败静默降级（[HostRepository.videoMeta](../app/src/main/java/com/example/boxtv/data/repository/HostRepository.kt) 失败统一返回 null），**该 40400 对用户不可见**，非本次症状直接来源

## 三、自动恢复机制定位

「数秒自动恢复」由三层机制叠加：

1. **ExoPlayer 内置重试**（主因）：`DefaultLoadErrorHandlingPolicy` 对 playlist/chunk 加载失败按指数退避（约 1s/2s/4s）自动重试，瞬时性 404（删除挂起解除）在重试窗口内自然恢复，用户表现为「卡一下自己好了」；
2. **删除挂起窗口期极短**：下载器/同步工具替换文件的挂起态通常毫秒~秒级；
3. **电视端无应用层重试**：一旦 ExoPlayer 重试耗尽触发 `onPlayerError`，[PlaybackActivity](../app/src/main/java/com/example/boxtv/ui/playback/PlaybackActivity.kt) 仅 Toast + `finish()` 退出播放页——用户几秒后手动重进即可恢复（因为文件此时已正常）。

**关键调用链**（症状发生时）：

```
电视端 ExoPlayer(HLS) → GET /api/video/part?videoId=..&u=..
  → 电脑端 requireDevice() → findByToken → touchDeviceLastSeen（⚠ 无锁回写，见 R3）
  → findFolder → PathGuard.resolve → file.exists()  ← 删除挂起/瞬时不可见 → false
  → respondError(404, 40400, "分片不存在")
  ← ExoPlayer DefaultLoadErrorHandlingPolicy 重试 → 恢复/耗尽后 onPlayerError
```

**监控盲区（为什么之前查不到）**：`AccessLogger` 只记录路由内显式打点的成功行为，**失败响应（404/403/5xx）完全不落日志**——40400 发生时电脑端日志里一片空白。

## 四、根因结论（按触发概率排序）

### R1（主根因）：播放文件瞬时不可见 / 不可读 —— Windows 文件系统竞态

分片或视频文件处于 **删除挂起态**（下载器替换文件、清理临时文件）或瞬时不可访问窗口期，`File.exists()` 返回 false，stream/part/meta 路由返回 40400。文件恢复后一切正常，完美吻合「非必现 + 随机 + 秒级自愈」。
旁证：授权目录内存在大量下载器产物（download.config、index.m3u8.bak、.key），说明该目录被下载工具持续管理。

### R2（并发伴生）：分片被独占锁定时静默下发空响应体

杀软实时扫描/下载器写盘持有独占锁 → part 返回 **200 + 0 字节**（无错误码、无日志），ExoPlayer 中途 EOF。此路径比 40400 更隐蔽。

### R3（代码缺陷，已修复）：`touchDeviceLastSeen` 无锁读改写整个配置对象

[ConfigStore.kt](../boxTV-host/src/main/kotlin/com/example/boxtv/host/core/ConfigStore.kt) 旧实现在**每个鉴权请求**上无锁重写 `config`（含 folders/devices 全量），与 `update()`（添加/移除授权文件夹、重新配对签发新 Token）并发时发生丢失更新——结构性变更被整体回退，电视端随即 40400「授权文件夹不存在」或 40100。该缺陷概率低（需用户恰在电脑端操作时电视端在持续请求），但后果严重且不自愈，必须修复。

### R4（缓解放大）：meta/播放列表缓存掩盖文件占用

只有缓存未命中窗口期才暴露文件问题 → 解释了「偶现」与「刚下载完/刚换文件的影片更容易触发」的潜在相关性。

## 五、复现步骤（可操作）

**场景一：40400「分片不存在」（R1 主根因）**

1. 电视端/模拟器进入播放某 M3U8 影片（HLS 直连，分片持续被请求）；
2. 电脑端 PowerShell 对任一分片执行（制造删除挂起）：
   ```powershell
   $fs=[IO.File]::Open('E:\视频\<分片路径>','Open','Read','Read, Delete')
   [IO.File]::Delete('E:\视频\<分片路径>')   # 句柄未关，文件进入删除挂起
   # 数秒后 $fs.Close() 解除 → 自动恢复
   ```
3. 观察：电视端播放异常（Toast ERROR_IO 或卡顿自愈），电脑端控制台/访问日志（升级后版本）出现 `HTTP 404 /api/video/part?...`。

**场景二：200 + 0 字节静默截断（R2）**

1. `$fs=[IO.File]::Open('<分片>','Open','Read','None')` 独占锁定；
2. 播放器请求该分片 → 收到 200 空响应体 → 中途 EOF；升级后版本改为显式 50000 + 访问日志留痕。

## 六、临时规避方案（升级前）

1. **播放卡顿/失败后等待 2~3 秒重进播放**——瞬时文件态解除后即可正常；
2. **播放期间避免在电脑端对影片目录做下载/整理/同步操作**（杀软可将 E:\视频 加入扫描排除项）；
3. 重启电脑端 boxTV 程序（若遭遇 R3 配置回退，这是唯一恢复手段）。

## 七、长期修复建议

| 编号 | 措施 | 状态 |
|------|------|------|
| F1 | `touchDeviceLastSeen` 改为与 `update()` 同锁的互斥读改写（消除配置丢失更新） | ✅ 已实施（1.2.3） |
| F2 | stream/part 下发文件前做**可读性预检**，文件被独占锁定时显式回 50000 并落日志，替代静默空响应 | ✅ 已实施（1.2.3） |
| F3 | 播放列表改写（m3u8.rewritten）加 IO 异常兜底，失败显式回错不再冒泡成无日志连接重置 | ✅ 已实施（1.2.3） |
| F4 | **失败请求监控**：HTTP 状态 ≥400 的请求自动落访问日志（含路径/查询串/耗时）+ 控制台输出 | ✅ 已实施（1.2.3） |
| F5 | TV 端 API 错误码埋点（tag `boxtv-api`）与播放器错误原因链日志（tag `boxtv-playback`，含 HTTP 状态码/URL/位置） | ✅ 已实施（1.3.10） |
| F6 | 播放器错误不再直接 finish，做 1 次应用层重试（HLS 场景重试价值高） | 建议，未实施 |
| F7 | 40400「分片不存在」短暂重查（200ms 间隔重试 2 次）后再回错，消除删除挂起窗口期的瞬时误判 | 建议，未实施 |
| F8 | `File.exists()` 误报防护：exists=false 时改用 `Files.exists(path)` 或再查一次父目录可访问性，区分「真不存在」与「瞬时不可见」 | 建议，未实施 |

## 八、新增异常监控点与日志埋点（后续定位同类问题的抓手）

**电脑端（1.2.3+）**

1. 访问日志新增「异常」动作：所有 HTTP ≥400 响应自动记录——`HTTP 状态码 + 完整路径查询串 + 耗时`，UI 访问日志 Tab 直接可见（此前失败请求完全无日志）；
2. 控制台同步输出 `[boxTV] FAILED HTTP xxx ...`，便于远程排查；
3. 「播放异常」动作：文件被占用不可读 / 播放列表读取失败，均记录文件名与底层 IOException 原因。

**电视端（1.3.10+）**

1. `adb logcat -s boxtv-api`：所有接口业务错误（40400/40100…）+ 完整 URL、网络异常（异常类名+消息）；
2. `adb logcat -s boxtv-playback`：播放器错误完整上下文——错误码（名称+数值）、播放位置、流类型（HLS/直连/转码）、当前流 URL、**最多 6 层异常原因链**（可从中直接读出 HTTP 404 的 `InvalidResponseCodeException.statusCode`）。

**排障口诀**：电视端播放异常 → 先看电脑端访问日志「异常」条目 → 无记录则抓 `adb logcat -s boxtv-api boxtv-playback` 对照原因链 → 40400 且电脑端有对应 HTTP 404 记录 = 文件瞬时不可见（R1）；无 404 记录但播放器报 EOF = 空响应体截断（R2，1.2.3 后会显式报错）。
